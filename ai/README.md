# ChainGuard AI Service

AI inference platform for the ChainGuard examination integrity system — a peer service to `backend/` and `frontend/`, per `docs/chainguard-ai-technical-design-phase3a.md`.

## Current status: Sprint AI-3 (training platform)

Sprint AI-1 built the infrastructure skeleton. Sprint AI-2 built a real dataset platform. Sprint AI-3 makes training real: a working training engine, experiment tracking, evaluation, model comparison, and model registry integration — all exercised against an actual YOLOv8 training run (see `ai/training/runs/smoke_test_6bc0803a/` for the real output). **There is still no inference and no frontend/backend integration** — that's Sprint AI-4, deliberately not started here. See `docs/chainguard-sprint-ai3-completion-report.md` (root `docs/` folder) and `docs/AI/` for task-oriented guides.

## Tech stack

- Python 3.12, FastAPI, Uvicorn
- Pydantic / pydantic-settings for config and validation
- Pillow, numpy, PyYAML, ImageHash — the dataset platform (Sprint AI-2); see `datasets/README.md` for why this is lighter than Albumentations/OpenCV
- pytest for testing

Future sprints add: Ultralytics YOLOv8, PyTorch, OpenCV, Albumentations — see `requirements-ml.txt` (not installed yet; nothing imports these packages this sprint).

## Getting started

```bash
cd ai
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
cp .env.example .env
pip install -r requirements.txt -r requirements-dataset.txt
```

**Run the API server:**
```bash
./scripts/start_dev.sh    # http://localhost:8000, auto-reload
# or: ./scripts/start.sh  # no reload
```

**Verify it's alive:**
```bash
curl http://localhost:8000/health
```
Interactive API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

**Generate a dataset** (see `datasets/README.md` for the full walkthrough):
```bash
python -m datasets.generator.cli --config datasets/configs/sample.yaml
python -m datasets.stats_cli --manifest datasets/manifest.csv
```

**Run the tests:**
```bash
pytest tests/ -v
```

**Docker** (also starts Postgres — backend/frontend aren't containerized yet, see the root `docker-compose.yml`'s comments):
```bash
cd ..  # repo root
docker compose up postgres ai
```

## What's real vs. what's a skeleton

| Real, working, tested | Still a skeleton (interface defined, `NotImplementedError` body) |
|---|---|
| `main.py`, `config/`, `utils/exceptions.py` | `training/train.py`, `training/callbacks.py` |
| `routers/health.py` | `evaluation/evaluate.py`, `evaluation/compare_models.py` |
| `services/model_registry.py` | |
| `schemas/common.py` | |
| **`datasets/` — the entire dataset platform (Sprint AI-2)**: config, manifest, versioning, generator (+ backgrounds, damage overlays, CLI), augmentor, validator, statistics, `BatchImporter` | `WebcamCollector` — real code, but **not testable in this sandboxed environment** (no camera device); see `datasets/README.md` |

Every skeleton file's docstring names the design-document section it implements and is written against, so a future sprint isn't guessing at intent.
